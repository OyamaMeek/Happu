## 当前阻塞与审批边界

格式处理是新子系统。`brainstorming` 已用于设计流程。前一轮已向用户呈现 ZIP 阶段设计并询问是否批准，但用户随后要求生成交接文档，没有批准或调整设计。因此该设计仍待确认；新对话应先读取该回复和本文件，再等待对 ZIP 设计的明确批准。尚未写 ZIP 规格、实施计划、产品代码，也未安装依赖。不能把最初的“完整复刻”授权解释为跳过新子系统的设计审批。

已调研到的建议是首个格式切片使用 SSZipArchive 2.6.0，通过 SwiftPM；支持密码 ZIP 解压。ZIPFoundation 不提供已确认的密码 API。SSZipArchive 多路径接口不会递归写所选目录，需要实例 API 遍历写入相对路径。解压库会净化越界路径、默认限制符号链接落在目标目录内，并能按条目报告进度/取消；单个大文件处理中无法确认即时取消。正式规格应把安全边界和延迟取消写准确，写入独立暂存目录，成功后再发布结果。

原版预览组件本地化资源有 `uncompress.passwd.input`（请输入解压密码）与 `file.archive.pwd.title`（设置密码）；字符串归属 `PreviewManagerRes.bundle/zh-Hans.lproj/Localizable.strings`，但不能单凭字符串断言设置密码对应 ZIP 导出入口。不要擅自把加密 ZIP 导出塞入已呈现设计，先核对用户审批后的范围。

PDFKit、ImageIO、AVFoundation/AudioToolbox 可处理部分常见 PDF、图像和媒体路径；实际输出能力须用 Apple 的编码器查询/运行检查，不以 UTType 或格式常量代替证据。MP3、WebP 是常见格式，不能因缺少原生输出就归为“少见格式”。XML/YAML 与 JSON/plist 转换需明确类型映射与不能无损转换的值。详见 `memory/plan.md` 和原版内置指南。
