# Shu 媒体处理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成四种视频容器、五种音频格式、音轨处理与区间剪辑、视频转动图及真实页面入口，继续保留完整复刻其余功能。

**Architecture:** 分别使用 AudioService、VideoService、VideoAnimationService，复用同工作区安全发布和已有处理页面交互模式。AVFoundation/AudioToolbox 分块处理媒体；LAME 补充 MP3，图片服务补充逐帧动画编码供视频采样调用。服务自检和 iOS hosted XCTest 验证相同产品实现，UI XCTest 从真实文件入口操作。

**Tech Stack:** Swift、SwiftUI、AVFoundation、AudioToolbox、CoreGraphics/ImageIO、libwebp 1.6.0、LAME 3.100.3。

**Spec:** `docs/superpowers/specs/2026-10-01-shu-media-design.md`；前置 PDF/图片 Task3 及阶段整体审查完成后再实施。

## Global Constraints

- main 直接开发、子代理顺序实施和普通自动推送已获授权；每个任务重新读取当前文件，保留用户 AGENTS.md 与 Xcode 用户数据改动。
- iOS 18 部署目标；iOS 26 使用系统 Liquid Glass。优先系统能力与已安装依赖，不新增媒体播放框架或通用任务调度层。
- 只处理工作区普通文件，拒绝越界、符号链接及祖先、原始 `.`/`..` 路径、非法名称和非目录目标；唯一隐藏暂存，重读验证，FileStore.rename/move 同卷无覆盖发布。失败/取消清理且不发布部分产物，输入保持完整，清理失败明确报错。
- 输出视频 MP4/MOV/M4V/3GP；音频 M4A/WAV/MP3/CAF/FLAC；动图 GIF/WebP。不能用少见格式例外跳过这些格式。
- 进度来自真实媒体时间/帧，取消检查贯穿读写和验证；关闭页面先取消并等待结束。原生单次调用存在取消延迟时如实说明。
- 不截图或进行图像检查；真实 PCM/帧内容断言、文字 XCTest 与结构化结果允许。Mac、Simulator/Device 构建、iOS 运行、交互与视觉分别记录，不能互相替代。

## Review Focus

- 低采样率或多声道音频：保留可表达参数，MP3 双声道下混须明确选择，不静默重采样；Task1 核对输出 PCM 和拒绝原因。
- 旋转、非零起始时间和声轨较短的视频：保持显示方向与真实时间线，不强行假定音轨长度等于视频；Task2 验证旋转显示、区间信号和声画时间。
- 多音轨及容器限制：保留可表达轨道，不能默认只留下第一条；Task2 核对两轨或明确选择/拒绝，Task4 验证表单选择。
- 29/30 fps 与非整秒短区间：按累计边界量化 GIF/WebP 时长，避免逐帧舍入积累误差；Task3 用实际编码元数据及帧信号验证。
- 取消与目标重名发生在发布前：取消后不产生结果、原文件和同名文件不变、可重新操作；各服务任务断言，Task4 用真实长输入交互回归。

### Task 1: 音频转换、安全输出与 iOS 实际编码验证

**Files:** Create `ShuReplica/MediaWorkspace.swift`, `ShuReplica/AudioService.swift`, `Tests/AudioSmoke.swift`, `Tests/MediaRuntimeTests.swift`, `ShuReplica.xcodeproj/xcshareddata/xcschemes/ShuReplica.xcscheme`；modify `Package.swift`、`Package.resolved`、`ShuReplica.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`、`ShuReplica.xcodeproj/project.pbxproj`、changelog。注册 hosted `ShuReplicaRuntimeTests` 目标，TEST_HOST 为真实 ShuReplica.app，测试 `@testable import ShuReplica`，共享 scheme 保留现有 UITests 并加入 RuntimeTests；不在产品增加测试入口。

**Interfaces:** `MediaWorkspace(root: URL)` 提供 `checkInput(_ input: URL) throws`、`checkOutput(folder: URL, name: String) throws`、`withStaging(progress: Progress, operation: (URL) async throws -> URL) async throws -> URL`、`publish(_ output: URL, in folder: URL, named name: String, progress: Progress) throws -> URL`。暂存生命周期包含编码、重读和发布，任何取消/错误均清理。`AudioFormat: String, CaseIterable` 为 m4a/wav/mp3/caf/flac。`AudioTrackInfo` 包含 `id: Int32`、`language: String?`、`channels: Int`、`sampleRate: Double`。`AudioService(root: URL)` 提供 `tracks(_ input: URL) async throws -> [AudioTrackInfo]`、`convert(_ input: URL, to format: AudioFormat, bitRate: Int, trackID: Int32?, downmixToStereo: Bool, in folder: URL, named name: String, progress: Progress) async throws -> URL`。单音轨 nil 自动选择；多音轨 nil 必须报出要求选择，ID 不存在明确失败。

- [ ] Step 2: 先写 AudioSmoke 真实 44.1/48 kHz 单/双声道 PCM（左440Hz/右880Hz、前后不同信号）、五格式 roundtrip、五 bitrates、视频音轨和多音轨 ID、六声道明确下混、8 kHz 与不支持组合、无轨/损坏/零长/越界/内部外部链接与点路径/非法名称/同名/真实读写失败/取消/清理。重新解码检查采样率、声道、时长和频率/分段内容；有损时允许≤0.15秒编码延迟及频率±5Hz、信号相关性>0.9，不能用文件非空判通过。`swift run --scratch-path DerivedData/MediaPackage AudioSmoke DerivedData/TestRuns/AudioRed` 应编译后因服务 stub 拒绝正常输入而失败；保存退出码和断言，不能将依赖/编译失败冒充行为 RED。

### Task 2: 视频转换、静音与剪辑

**Files:** Create `ShuReplica/VideoService.swift`, `Tests/VideoSmoke.swift`；modify MediaRuntimeTests、Package.swift/Xcode 注册和 changelog。

**Interfaces:** 消费 MediaWorkspace、AudioTrackInfo。`VideoFormat: String, CaseIterable` 为 mp4/mov/m4v/threeGP（rawValue3gp）；`VideoQuality` 为 original/high/medium/low；`VideoOperation` 为 convert/removeAudio/trim(start: Double, end: Double)。`VideoInfo` 包含 `duration: Double`、`width: Int`、`height: Int` 和 `audioTracks: [AudioTrackInfo]`，尺寸为显示尺寸。`VideoService(root: URL)` 提供 `info(_ input: URL) async throws -> VideoInfo`、`process(_ input: URL, operation: VideoOperation, to format: VideoFormat, quality: VideoQuality, audioTrackIDs: [Int32]?, in folder: URL, named name: String, progress: Progress) async throws -> URL`；nil 为全部原音轨，显式数组必须为存在且无重复 ID，removeAudio 忽略选择并移除全部音轨。

- [ ] Step 1: VideoSmoke 真实写运动/颜色标记、有方向变换、44.1/48kHz 分段声音、静音、两音轨、短声轨、非零开始时间的样本。测试四容器及 high/medium/low，包含2002×1002较大输入验证1920/1280/640实际降采样、64×64输入验证不放大，original兼容 passthrough/不兼容明确转码；核对可解码帧、方向/显示宽高比、轨道、时长（误差≤一帧+0.02秒）和区间信号。`swift run --scratch-path DerivedData/MediaPackage VideoSmoke DerivedData/TestRuns/VideoRed` 编译后应因正常转换未实现失败。
- [ ] Step 2: AVAssetReader/Writer 或可满足规格的原生 export；H.264+AAC，high/medium/low最长边1920/1280/640、码率8000000/4000000/1000000，音频192000，不放大、合法偶数且保持显示宽高比/方向。original在兼容目标时 passthrough，否则明确H.264/AAC；检测实际可表达轨道，目标不兼容多音轨则必须要求用户选择，不自动丢失。所有媒介从一致时间原点写入，保留轨道实际间隔；帧/PCM缓冲按块释放，失败cancelReading/cancelWriting并清理。
- [ ] Step 3: removeAudio 无音轨明确失败，结果只有视频；trim要求有限且 `0≤start<end≤duration`，重置输出时间至零，保留区间声音/视频同步。测试0起点、末尾、短区间、无视频/坏文件/空与超范围/非法值/音轨ID/同名/链接与点路径/真实取消和写失败，断言原文件、哨兵及暂存。VideoGreen退出0，hosted `testVideoContainersAndEdits` 实际处理四容器、旋转、有/无音轨与剪辑后重读通过。
- [ ] Step 4: 服务相关检查、三种顺序构建、真实 hosted 方法结果、自查/changelog/原子提交 `feat: add video conversion and editing` 与普通 push、独立审查。不以 Mac 成功替代 iOS 运行。

### Task 3: 逐帧编码与视频转动图

**Files:** Create `ShuReplica/VideoAnimationService.swift`, `Tests/VideoAnimationSmoke.swift`；modify ImageService/ImageSmoke、MediaRuntimeTests、Package.swift/Xcode 注册和 changelog。

**Interfaces:** `AnimationQuality` 为 original/best/higher/high/medium/low；`AnimationColor` 为 full/webSafe/grayscale/blackWhite。`VideoAnimationService(root: URL)` 提供 `convert(_ input: URL, start: Double, end: Double, fps: Int, to format: ImageFormat, quality: AnimationQuality, color: AnimationColor, loop: Int, in folder: URL, named name: String, progress: Progress) async throws -> URL`，format仅gif/webp。ImageService 增加 `encodeAnimation(frameCount: Int, frameAt: (Int) throws -> CGImage, durations: [Double], loop: Int, to format: ImageFormat, quality: Double, in folder: URL, named name: String, progress: Progress) throws -> URL`；按需取得同尺寸帧，复用现有 ImageIO/libwebp writer 与安全发布，禁止收集所有未压缩CGImage。旧convert/extract/compose行为保持。

- [ ] Step 1: ImageSmoke 为新逐帧API写真实帧序/信号/有限循环与无限循环/参数/取消测试，调用次数覆盖实际逐帧编码和验证；新 VideoAnimationSmoke 使用有方向和颜色/时间标记视频测试GIF/WebP、1/10/29/30fps、0/1/4循环、所有质量颜色、非整秒与短区间、限制拒绝。先运行编译后的 stub 行为RED，不能用不编译证明实现不存在。
- [ ] Step 2: AVAssetImageGenerator 应用方向，按 `start+i/fps` 顺序采样，采样数为ceil((end-start)*fps)，末帧覆盖end；控制允许误差或明确失败，避免取区间外帧。采样可先存独立暂存PNG再由frameAt逐帧解码，结束及时释放。最长边quality为原画/1280/960/720/480/320且不放大；fps1–30默认10，loop0–65535，四颜色为默认编码器量化/web-safe216/灰度/亮度阈值0.5。WebP质量1，GIF由ImageIO量化。
- [ ] Step 3: GIF/WebP时长由累计边界量化为百分之一秒/千分之一秒，帧差为相邻边界差，最终总长误差≤0.01/0.001秒；GIF不能逐帧独立round导致总长漂移。每个量化后差必须>0，末帧无法表达时开始前要求调整区间/fps，测试此拒绝、原输入与清理；不能用零时长播放器默认值或删除帧掩盖。单帧4000万像素、总8000万像素、1000帧和WebP尺寸限制开始前检查，超限明确要求调整而不截断。帧验证同样逐个读取释放，GIF/ImageIO正循环值为归一化总播放次数，WebP映射一致，重复帧不得丢失。
- [ ] Step 4: `swift run --scratch-path DerivedData/MediaPackage VideoAnimationSmoke DerivedData/TestRuns/AnimationGreen`、完整ImageSmoke和相关媒体回归退出0；hosted `testVideoAnimations` 在iOS实际验证两codec帧数/内容/时长/循环，Simulator/Device/build-for-testing顺序构建。自查/changelog/精确暂存、提交 `feat: add configurable video animation conversion`、普通push与独立审查。
