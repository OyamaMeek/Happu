# Shu 文件工作区与 Liquid Glass 设计

## 目标与边界

用户要继续扩展现有 `ShuReplica` iOS 工程，最终覆盖本地 `Payload/Shu.app` 可证实的页面和主要操作，并在 iOS 26 使用 Liquid Glass。此规格是第一个可独立验证的阶段：完成三栏导航的系统外观，以及文件工作区的批量整理和系统文件导入导出。部署目标维持 iOS 18.0；在 iOS 26 上使用系统提供的玻璃外观，在旧系统上使用对应的系统外观。

后续阶段分别处理预览与常见格式、下载完整流程、Wi-Fi/WebDAV 传输与更多设置。罕见格式可以明确提示当前不支持；不能生成损坏或误标为成功的输出。各阶段完成后，合并构成用户要求的完整复刻。

## 依据与不确定性

- `Payload/Shu.app/Info.plist` 标识 Shu 1.2.4、文档类型与 `shu` URL scheme；见 `work/payload-liquid-glass/evidence/E-001.md`。
- 中文本地化资源包含“文件、下载、更多”三栏及文件归组、导入、导出、批量操作入口；见 `work/payload-liquid-glass/evidence/E-002.md`。
- 内置指南说明一键归组、ZIP 导出、系统文件与相册传输等用户操作；见 `work/payload-liquid-glass/evidence/E-003.md`。
- 当前没有原版运行界面或截图证据。栏目和操作有静态证据；具体间距、动效与每个格式的运行行为尚无证据。本项目采用新的系统界面样式，不把静态资源推断成像素级布局。

## 方案选择

| 方案 | 适用情况 | 本次结论 |
|---|---|---|
| 扩展现有 SwiftUI 工程 | 可复用已有 `FileStore`、下载逻辑与三栏页面；系统控件在新系统上获得 Liquid Glass | 采用，用户已确认 |
| 用 UIKit 重建界面 | 需要精确控制旧版界面的自定义布局和转场 | 当前缺少原版运行画面，且会重写现有流程 |
| 新建独立 Swift 工程 | 现有工程无法继续维护时 | 当前工程可构建且核心文件操作已有测试 |

本阶段只使用 SwiftUI、Foundation 和已随系统提供的框架，不增加第三方依赖。系统 `TabView`、导航栏和工具栏负责玻璃导航层；若增加自定义悬浮操作按钮，仅该控件在 iOS 26 使用 `glassEffect`，并保留旧系统样式。列表内容不叠加玻璃材质，确保文字与文件预览清楚。此用法依据 [Apple 的材料设计指南](https://developer.apple.com/design/human-interface-guidelines/materials)和[自定义视图指南](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)。

## 页面与交互

### 三栏导航

`ShuReplicaApp` 保留“文件、下载、更多”三个顶层栏目。每栏拥有自己的 `NavigationStack`，切换栏目时保持各自的导航状态。文件栏的新增与编辑操作置于系统工具栏；下载与更多栏目在本阶段保持现有可用行为。所有图标按钮都有可读的辅助功能标签，动态字体下不依赖固定尺寸容器。

### 文件首页与文件夹

文件首页显示工作区入口、下载、共享和现有九种内建分类。内建分类对应 `Documents` 下的真实目录；目录仅在工作区初始化时建立，不在每次打开页面时重复写入。文件夹显示目录与文件，支持搜索、按名称或修改时间排序、进入子目录、QuickLook 预览、新建文件夹、重命名、复制、移动、删除和系统分享。现有文件操作及避免同名覆盖的行为继续保留。

### 一键归组

用户可在工作区根目录对未归类的直接子文件执行“一键归组”；在其它普通文件夹中，可对单个文件或所选文件执行归组，目标始终是工作区根目录下的内建分类。归组不递归进入子目录，也不移动 `Downloads` 或“共享”中的内容。文件类型按明确的扩展名和 `UTType` 分类，顺序优先识别电子书、归档、磁盘镜像和脚本，再识别一般文稿、图片、视频及音频。无法可靠分类的文件留在原位置，并显示处理与跳过数量。同名目标使用现有唯一命名规则；移动失败的文件保留在原位置，并显示失败原因。

### 批量操作

文件夹提供编辑模式，允许全选、反选和取消选择。选中的文件或目录可复制、移动、分享和删除；归组只对可分类的普通文件开放。批量删除在确认后执行。操作完成后刷新当前目录并清空选择；若部分项目失败，列出成功和失败数量及失败项，不把部分成功显示为全部成功。复制或移动目录仍遵守 `FileStore` 的工作区边界及“不能移入自身子目录”约束。

### 系统文件导入导出

保留系统 `fileImporter` 的多选导入，取得外部文件时使用安全范围访问，并将副本保存到当前文件夹。`UIFileSharingEnabled` 与系统分享入口继续提供文件 App、电脑文件共享及其它 App 的交互。相册、通讯录、相机扫描和局域网传输将在后续各自的规格中处理。

## 数据流与失败处理

`FileStore` 仍是本地文件操作的唯一入口；文件 URL 和真实目录是数据来源，页面只保存当前路径、搜索词与选择集合。归组和批量操作使用同一套文件边界、名称检查与唯一命名规则。界面在操作后重新读取目录，不长期缓存第二份文件索引。

输入名称为空、包含路径分隔符或越过工作区边界时，在操作处报错。外部导入失败、磁盘空间不足、目标被移走或批量操作部分失败时显示具体结果；不覆盖已有文件，不静默丢弃错误。共享目录中的用户文件仍由用户显式管理，归组不会改动它。

## 验收与验证

1. 在真实临时工作区创建可分类文件、未知类型文件及重名目标，归组只移动预期文件，保留未知文件和原内容。
2. 批量复制、移动、删除验证选择范围、重名处理、子目录防护与部分失败结果；基础文件操作自检继续通过。
3. 系统导入在权限获得与拒绝时都给出可理解结果；导入后的文件可预览、分享及再次读取。
4. 使用 Xcode 27 编译 generic iOS Simulator 与 Device；iOS 26 API 均有可用性保护，部署目标保持 iOS 18.0。
5. 有可用模拟器或设备时，运行三栏切换、导航、动态字体与文件操作。当前机器的 CoreSimulatorService 无法连接；若实施时仍不可用，明确记录运行验证缺口。未经用户要求，不主动截图或进行视觉检查。

本阶段完成后，文件页面与已有下载页面均保持可用；后续规格继续覆盖完整复刻的其余功能。
