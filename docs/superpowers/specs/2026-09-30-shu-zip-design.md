# Shu ZIP 归档设计

## 目标与授权

继续交接文件中的首个格式处理切片。用户在本会话明确要求读取交接后直接在 main 开发、自动推送；沿用子代理分步实施与复查。此次直接执行要求优先于旧交接中的逐阶段审批等待。后续 PDF、图片、媒体、文本、下载增强和传输设置仍是完整复刻的剩余阶段。

## 操作与数据流

- 文件夹单项上下文菜单和批量操作提供“打包为 ZIP”，支持文件、嵌套目录、空目录和中文名称；输出普通 ZIP，不增加加密导出。
- ZIP 单项提供“解压”和“解压到…”，默认当前文件夹；目的目录仅从工作区选取。密码输入使用 SecureField，普通 ZIP 可留空，错误密码明确报错并允许重新发起。
- 打包可以指定 ZIP 名称。结果同名自动编号，解压结果放入按归档名称命名的独立目录，保留源文件。
- 处理页显示进度、取消、失败原因和成功结果；成功后可系统分享，ZIP 可 QuickLook 预览，解压目录返回列表即可导航。后台串行处理，关闭处理页与取消均请求停止。
- 取消在条目边界生效，单个大条目期间可能延迟；显示“正在取消”并等实际任务结束。失败和取消清理未发布结果。
- RAR、7z、tar、压缩镜像等入口明确提示当前格式不支持解压，不把名称识别当作处理能力。

## 实现边界

Foundation + SSZipArchive 2.6.0，SwiftPM 精确版本；Xcode 的产品名和模块名是 ZipArchive，官方来源为 https://github.com/ZipArchive/ZipArchive/tree/2.6.0 。保持 iOS 18.0 部署目标及现有系统导航。

ArchiveService 同步处理真实文件，由处理页在后台调用。每项任务在工作区隐藏的独立 UUID 暂存目录中创建输出，成功且未取消后通过 moveItem 发布。同名编号、失败清理与路径检查统一在服务内；不覆盖目的文件。

所有输入与目的目录校验真实路径在工作区内。根目录不能作为打包输入；拒绝输入符号链接与目录内符号链接，拒绝重复顶层名称与重复／重叠选择。目的目录不存在时明确失败。隐藏文件也需保留，临时目录不得被打包。

解压使用成熟库的路径净化和符号链接安全检查，要求越界条目不能写出暂存目录。解压结果中的符号链接拒绝发布；危险路径允许库安全净化或明确拒绝。真实恶意 ZIP 验证暂存外文件未产生、原有文件未改变。密码、损坏数据、磁盘写入与关闭归档失败必须报告；仅全部成功才发布。

## 验证与交付

用直接调用产品服务的 macOS SwiftPM 可执行自检验证真实 ZIP 往返；Python zipfile 只生成标准兼容性及危险路径测试归档，系统 zip 生成独立密码 ZIP，系统 unzip 读取产品输出。覆盖嵌套／中文／空目录、普通与密码解压、错误密码、损坏归档、同名、不合法目标、越界／链接、取消及清理。

每个片段先新增能够暴露缺失行为的测试并记录失败，再实现和记录通过。运行现有五项 Swift 自检，generic Simulator、Device 和 UI target 构建。已知 XCTest runner 启动阻碍不重复尝试；本次以服务真实测试、构建及模拟器安装启动验证，未获授权不截图。逐任务独立审查，完成后提交、普通推送 main，并记录 changelog 和可见消息归档。
